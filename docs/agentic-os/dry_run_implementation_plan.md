# Dry-Run Validation Harness Implementation Plan

## 1. Endpoint Strategy
We will extend the existing `TruthQueryRequest` Pydantic model to include a new boolean flag instead of using a query parameter.
```python
class TruthQueryRequest(BaseModel):
    # existing fields...
    dry_run: bool = Field(default=False, description="V2 feature toggle to execute without mutating state")
```
**Benefits:**
- 100% backward compatible: Clients not sending the flag default to `False`.
- Keeps the REST interface clean without mixing query parameters and JSON payloads on a POST request.
- Centralized validation inside the payload model itself.

## 2. Insertion Strategy in `main.py`
The exact insertion point is immediately after string composition but before any database operations:
- **File:** `apps/truth-api/app/main.py`
- **Hook Point:** Right after `response = compose_response(payload.message, puzzles, case_ctx=case_ctx)` (around line 346).

**Early-Return Design & Guards:**
```python
    response = compose_response(...)

    # --- NEW V2 INJECTION SEAM ---
    if payload.dry_run:
        # 1. Generate local Hypothesis ID
        # 2. Construct LLM Call with V2 templates
        # 3. Strip Output -> Validate JSON
        # 4. Return DryRun validation payload directly
        return execute_v2_dry_run_pipeline(...)
    # -----------------------------

    # EXISTING SAFEGUARDS: Because we return early, we inherently bypass:
    if case_ctx:
        _attempt_blueprint_writeback(...) # Guarded! No blueprint updates.
    
    _write_session_memory(...) # Guarded! No session logs.
```
By returning early, we inherently prevent both canonical promotion and any SQLite/LanceDB writes.

## 3. V2 Dry-Run Pipeline Sequence
When `dry_run=True`, the wrapper executes the following sequence:

1. **UUID Generation:** Generate a local `uuid.uuid4().hex` for the `hypothesis_id`.
2. **Context Assembly:** Combine user message, `case_ctx.address_as`, and retrieved puzzles.
3. **LLM Inference:** Call the existing LLM provider (using prompt templates from `/prompts/` and `/templates/`). We will request a combined JSON object containing the Reflection, Blueprint Instance, and Review arrays.
4. **Markdown Stripping:** 
   Execute a regex or string manipulation step:
   ```python
   raw_text = raw_text.strip()
   if raw_text.startswith("```json"):
       raw_text = raw_text[7:]
   if raw_text.endswith("```"):
       raw_text = raw_text[:-3]
   ```
5. **JSON Parsing & Injection:** Parse to a dict. Forcefully inject the locally generated `hypothesis_id` into the JSON structure to prevent the LLM from hallucinating an invalid ID.
6. **Schema Validation:** Use `jsonschema.validate` against the loaded `.schema.json` files from `schemas/`.
   - Validate `case_reflection.schema.json` payload (if applicable)
   - Validate `blueprint_instance.schema.json` payload
   - Validate `promotion_record.schema.json` payload (with static logic enforcing `promotion_decision: false` and generating a rejection audit payload).

## 4. UUID Strategy
- **Where generated:** Inside the `TruthOS` Python backend, exactly at the start of the `dry_run` block in `main.py` or its handler.
- **Why not the LLM:** LLMs hallucinate universally unique identifiers poorly and may reuse strings from previous prompts. A cryptographically sound UUIDv4 must be generated by the host OS.
- **Propagation:**
  - Standardize `hypothesis_id` = `uuid4()`.
  - Inject into the JSON dict representation of `case_reflection`.
  - Inject into the JSON dict representation of `blueprint_instance`.
  - Pass the exact same string into the `promotion_record` as `reference_id`.
  - Include it as the tracking ID in the `audit_event`.

## 5. Output Contract
See `dry_run_response_contract.md` for the exact JSON structure.
The endpoint will return a 200 OK with a special format mapping the successful (or failed) dry-run execution, entirely bypassing the legacy `TruthQueryResponse`.

## 6. Minimal Implementation Sequence
1. **Schema & Template Pre-loading:** Create a `app/v2_schema_loader.py` utility that loads and caches the `schemas/*.schema.json` and `templates/*.md` files into memory on startup. Write solitary unit tests for this.
2. **Markdown Stripping Utility:** Write a purely functional `strip_markdown_json(text: str) -> dict` in a helper file with pure unit tests.
3. **Extend Payload:** Update `TruthQueryRequest` with `dry_run: bool = False`. Test that nothing breaks.
4. **LLM Client Wrapper:** Write a dedicated `app/v2_dry_run_agent.py` that takes the `case_ctx`, makes the LLM call using the newly loaded templates, strips the JSON, injects the UUID, and returns the dict.
5. **Main Injection:** Inject the `if payload.dry_run:` block into `main.py` calling the wrapped agent and returning the special schema response.
6. **Execute Test:** Fire a POST to `/api/truth/query` with `dry_run: true`.

## 7. Rollback Approach
Because the `dry_run` flag is strictly default-false, a problem only impacts API clients actively setting the flag.
If the insertion block itself causes an issue (e.g., import errors or syntax errors), it is a clean commit that can be reverted affecting no legacy code logic.
